# Set up Fahim's invitation

The app runs an honest preview without database settings. A private invitation link, successful saving, admin controls, and real metrics require Supabase. Preview does not save a response.

1. Install Node.js 22+ and run `npm ci`.
2. Copy `.env.example` to `.env.local`. Keep this file out of Git. Set the public Supabase URL/publishable key, server-only service-role key, a random 32-byte invitation session secret, one UUID for `INVITATION_ID`, and the exact `APP_URL` origin. The same secret must be configured on every Vercel instance; rotating it signs recipients out.
3. Create a Supabase project or use the local Supabase CLI stack. Run `npx supabase start` for local development. Run `npx supabase db reset` **only on the disposable local stack** to apply migrations. For a hosted project, review `supabase/migrations/202610130001_invitation.sql`, link the correct project with `npx supabase link --project-ref PROJECT_REF`, then apply with `npx supabase db push`. Do not run a reset on hosted data.
4. In Supabase Auth, disable public signup and provision Fahim's admin email/password. Set `ADMIN_USER_ID` to that Auth user's UUID. An ordinary Auth account has no dashboard access until its owner membership is created.
5. Run `npm run bootstrap`. It creates the invitation, its initial immutable configuration snapshot, owner membership, and a fresh private recipient link. The link prints once to your terminal. Store it privately; do not paste it into Git/issues. Re-running adds another link, preserving existing configuration. Bootstrap is setup-only and uses the service-role key.
6. Set the Supabase Auth site URL to `APP_URL`. Allow the exact recovery redirect `APP_URL/auth/callback`. For PKCE email recovery, keep the default `ConfirmationURL` email template and open the recovery link in the same browser that requested it. Local Supabase's mail viewer can receive test recovery emails. Open `/admin/login`, customize the English invitation, publish, then create a separate link for testing. The gift link permits one final response across browsers/devices.
7. Run `npm run dev`; open `http://localhost:3000`. The admin can use `/admin`, while the recipient opens the generated `/#invite=TOKEN` private link. The browser removes the fragment immediately, then exchanges that bearer token for a signed HttpOnly cookie; fragments never enter HTTP request URLs or platform URL logs. The legacy `/invite/TOKEN` route remains compatible but includes the bearer token in its initial HTTP request URL; use only generated fragment links to avoid platform URL logs. Anyone given the bearer link can use it: it is private access, not verified identity.

Use `npm run typecheck`, `npm test`, `npm run lint`, and `npm run build` before deployment. Database verification must use the local schema and authenticated/anonymous roles; do not infer RLS correctness from UI screenshots. `supabase/tests/security.sql` is a rollback-only local database assertion fixture; execute with `psql` against the local Supabase connection after migrations. It uses disposable local Auth rows and rolls back all changes.

Deploy the source to your own Git repository and import it into Vercel. Set the same environment variables there, change `APP_URL` to the final HTTPS origin, and allow its exact Supabase recovery redirect. The service-role key bypasses RLS; it stays in server-only modules and is used for explicit recipient authorization, transactional saving, validated configuration publication after admin verification, setup, and persistent rate limiting. Admin operations use verified user sessions and owner-aware RLS. Secrets and temporary local test accounts must never be committed. Preview deployments require their own origin and preferably a separate test Supabase project.

Recipient drafts exist only in browser memory. Completed responses and their wording snapshots persist together. Duplicate retries return the original response; different answers conflict. Deletion removes the response but retains the recipient's completed marker, so deleting never reopens the link. Revoke a link by setting its `revoked_at` using a trusted owner/database operation. For a new invitation after a completed or deleted response, create a new link in the dashboard; there is no implicit reopen. Recipient link expiry is 90 days and scoped browser sessions last at most seven days. Expired rate counters are deleted as new limits are consumed; counters contain HMAC hashes, not private messages, passwords, or raw tokens.

No hosted project, production account, or live deployment is created by the source files. Finish setup with the owner's Supabase/Vercel access and personal copy, verify a real save through a test link, then approve the final production release.

Primary implementation references: [Supabase SSR](https://supabase.com/docs/guides/auth/server-side/creating-a-client), [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Next.js Proxy](https://nextjs.org/docs/app/api-reference/file-conventions/proxy).

## Ready local setup helper

When the local Supabase stack is running, `npm run setup:local` prepares a disposable local admin, initial invitation and private gift link. It refuses to overwrite hosted configuration. It stores keys only in ignored `.env.local` and private local access details in ignored `.local-access.txt`, both with restricted permissions. Open that access file privately for the local login and invitation link. The dev server uses `http://127.0.0.1:3000`; set APP_URL to the exact origin you open. Local credentials are not a production admin account.

The latest mouse-only playful No behavior is part of the recipient UI. Yes is fixed; No chooses an empty on-screen resting place and avoids other controls. Keyboard and touch permit normal declines. No client-side draft writes occur during this interaction.
